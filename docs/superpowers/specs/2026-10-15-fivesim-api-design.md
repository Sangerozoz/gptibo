# 5SIM API 接入设计

**日期：** 2026-10-15  
**状态：** 用户已确认实施范围

## 目标与范围

今天给 Worker / D1 后端接入 5SIM 的服务端适配层，并在后台“服务接入”显示配置状态、提供仅管理员可用的只读连接检测。Codex 接码商品的订单绑定、真实购号、查码展示、财务核算和上架留到下一阶段。现有演示订单行为不因配置 API 密钥而自动变成真实采购。

## 设计

- 使用 Worker 私密变量 `FIVESIM_API_TOKEN`，只在服务端请求中作为 Bearer token。域名固定为官方 `https://5sim.net`；前端、日志和管理接口均不返回 token。
- 独立客户端封装 `profile`、按国家及产品查询价格、购买激活号码、检查订单、完成订单、取消订单。接口参数严格校验；响应校验关键字段，限制体积、超时并拒绝重定向。购号是有副作用的 GET，不自动重试；响应丢失时向调用者报告结果不确定，后续订单集成必须先核对原采购单。
- 管理员接口 `GET /api/admin/fivesim/status`：未配置时返回配置状态；已配置时调用 `profile` 并只返回连接状态和余额。`/api/admin/overview` 仅报告密钥是否存在。后台按钮手动触发检测，不在页面加载时访问 5SIM。
- 价格查询是供应商参考报价，不自动改动本站售价。金额单位以 5SIM 原始数值保留，不假定币种或汇率。

## 验收

- Mock 测试覆盖 Bearer 鉴权、URL/参数、安全响应解析、无库存、HTTP/超时/无效数据、购号结果不确定，以及管理员鉴权和只读状态接口。
- 商品保持下架状态；无真实购号和上架动作。无 token 时明确提示待配置，且不调用上游。
- `npm test`、`npm run build`、`npm run lint`、`git diff --check` 通过后提交并推送。
